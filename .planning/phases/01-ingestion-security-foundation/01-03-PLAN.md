<objective>
Implement the FastAPI webhook endpoint receiving Google Pub/Sub push messages (validating OIDC signatures). Check event `historyId` and `message_id` in Redis to ensure idempotency and prevent duplicate processing (implementing D-06). Dispatch email processing tasks immediately to Celery workers out-of-band to prevent webhook connection timeouts. Configure Celery task retry logic with exponential backoff and route failed payloads to a PostgreSQL Dead-Letter Queue (DLQ) table.

Purpose: Setup the event-driven async processing queues, idempotency safeguards, and error fallback handlers.
Output: FastAPI webhook endpoint, Celery task workers definitions, retry/DLQ routes, and test configurations.
