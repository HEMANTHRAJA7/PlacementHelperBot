## E2E Integration Audit

The system features robust vertical wiring across all major architectural boundaries:
1. **Security boundary**: Sensitive client tokens, register numbers, and IDs are encrypted using AES-256 Fernet keys on DB write, and decrypted on demand inside processing pipelines.
2. **Ingestion boundary**: Google Cloud Pub/Sub POST requests are authenticated using OIDC JWT signature checking. Incoming messages undergo Redis idempotency checks before Celery task execution, avoiding duplicate pipelines.
3. **AI / Scanning pipeline**: Background tasks download message bodies, match identifiers (with OCR/multimodal Vision fallback if needed), send Pydantic-structured AI categorization requests to Gemini, and format normal-priority Telegram notifications.
4. **Reminder engine**: Scheduler task processes deadlines every 5 minutes and uses a 2-hour catch-up window to guarantee alert delivery without duplicate notifications.
5. **Observability**: Metrics and JSON-formatted system status endpoints monitor the end-to-end stack's health.
